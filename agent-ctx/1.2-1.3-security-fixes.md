# Task 1.2 + 1.3: Security Fixes

## Agent: Security Fix Agent
## Status: Completed

### Fix 1 (Task 1.2): Admin Password Change Without Verification

**Problem**: Admins could change their password without providing the current password, unlike customers who must verify via `currentPassword`.

**Changes Made**:

1. **`src/lib/validations.ts`** — `adminPatchSchema`:
   - Added `currentPassword: z.string().optional()`
   - Added `.refine()` ensuring if `password` is set, `currentPassword` must also be present
   - Validation error path points to `currentPassword` field

2. **`src/app/api/admins/route.ts`** — PATCH handler:
   - Imported `verifyPassword` from `@/lib/auth`
   - Destructured `currentPassword` from validated data
   - Self-password-change check: if `admin.id === id`, verify currentPassword against stored hash
   - Returns 400 "Mot de passe actuel incorrect" on mismatch
   - Returns 404 "Administrateur introuvable" if target admin doesn't exist
   - Other admins can change a target admin's password without currentPassword (admin override)

### Fix 2 (Task 1.3): Protect Seed Endpoint in Production

**Problem**: Unauthenticated seed during bootstrap allows an attacker on a fresh deployment to inject their own admin.

**Changes Made**:

1. **`src/app/api/seed/route.ts`** — POST handler:
   - Added `SEED_TOKEN` env variable read at module level
   - Rate limiter: in-memory Map tracking per-IP attempts (max 3/60s), returns 429 with Retry-After header
   - Bootstrap mode (no admin exists):
     - In production: requires `seedToken` from body or query param matching `SEED_TOKEN` env var
     - If `SEED_TOKEN` not configured in production: returns 500 with configuration guidance
     - If token mismatch: returns 401 "Token d'initialisation invalide"
     - In development: allows unauthenticated bootstrap for convenience
   - Existing admin mode: unchanged (requires admin auth)
