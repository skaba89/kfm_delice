# Task 1.5 — Customer Relations FK Migration

## Summary
Migrated Order, Reservation, and Review models from `customerName` (string) to `customerId` (FK) while maintaining backward compatibility.

## Files Modified
1. `prisma/schema.prisma` — Added `customerId String?` + `customer Customer?` relation + `@@index([customerId])` to Order, Reservation, Review; added reverse relations to Customer
2. `src/app/api/orders/route.ts` — FK-based customer filtering, include customer relation, set customerId on POST
3. `src/app/api/reservations/route.ts` — Same pattern as orders
4. `src/app/api/reviews/route.ts` — Include customer relation on GET, set customerId on POST
5. `src/app/api/seed/route.ts` — Build customerMap, set customerId on matching seed records
6. `src/lib/validations.ts` — Added `customerId: z.string().optional()` to 5 schemas

## Database Migration
- Ran `npx prisma db push` successfully
- New columns: `Order.customerId`, `Reservation.customerId`, `Review.customerId` (all nullable String)
- New indexes on all three customerId columns

## Backward Compatibility
- `customerName` kept as display/fallback field
- `customerId` is optional — walk-in orders still work
- Customer queries use `OR: [{ customerId: id }, { customerName: name, customerId: null }]` to catch both FK-linked and legacy records

## Lint
No new errors introduced.
