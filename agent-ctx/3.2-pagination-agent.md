# Task 3.2: Add Pagination to API Endpoints

## Summary
Added server-side pagination to 5 key API list endpoints using Prisma `skip`/`take` for efficient DB-level pagination.

## Files Created
- **`src/lib/pagination.ts`** — Reusable pagination utility with:
  - `PaginationParams` / `PaginatedResponse<T>` TypeScript interfaces
  - `parsePagination(searchParams)` — extracts and validates `page` (min 1) and `limit` (1–100, default 20) from URL query params
  - `paginate<T>(items, page, limit)` — in-memory pagination helper (for non-DB cases)
  - `prismaSkip(page, limit)` / `prismaTake(limit)` — Prisma offset/limit helpers

## Files Modified (5 endpoints)

### 1. `src/app/api/orders/route.ts`
- Added `import { parsePagination, prismaSkip, prismaTake } from "@/lib/pagination"`
- Both customer-filtered and admin query branches now use `skip`/`take`
- Added `db.order.count({ where })` with `Promise.all` for parallel execution
- Response format: `{ data: [...], pagination: { page, limit, total, totalPages, hasNext, hasPrev } }`
- Empty-restaurant early return now returns paginated empty response

### 2. `src/app/api/reservations/route.ts`
- Same pagination pattern as orders
- Both customer-filtered and admin branches paginated
- Response format updated from array to `{ data, pagination }`

### 3. `src/app/api/reviews/route.ts`
- GET handler signature changed from `GET()` to `GET(request: Request)` to access URL params
- Single query branch (public, filtered by restaurantId) paginated
- Response format updated from array to `{ data, pagination }`

### 4. `src/app/api/invoices/route.ts`
- Admin/manager-only endpoint paginated
- Response format updated from array to `{ data, pagination }`

### 5. `src/app/api/customers/route.ts`
- Admin-only endpoint paginated
- No WHERE clause — uses `db.customer.count()` without filter
- Response format updated from array to `{ data, pagination }`

## Pagination Details
- **Default**: `page=1`, `limit=20`
- **Max limit**: 100 (clamped)
- **Min page**: 1 (clamped)
- **Query params**: `?page=2&limit=50`
- All `findMany` + `count` queries run in parallel via `Promise.all`

## Breaking Change Notice
All 5 endpoints changed response format from returning a bare array `[...]` to `{ data: [...], pagination: {...} }`. Frontend consumers will need to update to access `response.data` instead of using the response directly.
