# Task 2.1 — Migrate from SPA mode switching to Next.js App Router

## Summary

Migrated the RestoProGN project from a single-page application with `useState` mode switching to proper Next.js App Router route files, while keeping backward compatibility with all existing components.

## Files Modified

1. **`/src/app/page.tsx`** — Replaced the complex SPA mode-switching logic with a simplified public page. Removed the `AppMode` type, `useState<AppMode>`, and all conditional rendering based on `mode`. The page now uses `router.push()` for navigation instead of `setMode()`. Retained seed DB effect and WhatsApp floating button.

## Files Created

2. **`/src/app/admin/login/page.tsx`** — Admin login page. Wraps `AdminLogin` component in `AuthProvider`. Redirects to `/admin` if already authenticated. Uses `useEffect` for redirect to avoid SSR issues.

3. **`/src/app/admin/page.tsx`** — Admin dashboard (protected). Wraps `AdminDashboard` in `AuthProvider`. Redirects to `/admin/login` if not authenticated as admin.

4. **`/src/app/client/login/page.tsx`** — Client login page. Wraps `CustomerLogin` in `AuthProvider`. Redirects to `/client` if already authenticated. Navigation callbacks use `router.push()`.

5. **`/src/app/client/register/page.tsx`** — Client register page. Wraps `CustomerRegister` in `AuthProvider`. Redirects to `/client` if already authenticated.

6. **`/src/app/client/page.tsx`** — Client account (protected). Wraps `CustomerAccount` in `AuthProvider`. Redirects to `/client/login` if not authenticated. `onTrackOrder` callback navigates to `/tracking?orderId=...`.

7. **`/src/app/driver/login/page.tsx`** — Driver login page. Wraps `DriverLogin` in `AuthProvider`. Redirects to `/driver` if already authenticated.

8. **`/src/app/driver/page.tsx`** — Driver dashboard (protected). Wraps `DriverDashboard` in `AuthProvider`. Redirects to `/driver/login` if not authenticated.

9. **`/src/app/tracking/page.tsx`** — Delivery tracking page. Fetches order by `orderId` query param using `/api/tracking`. Wraps `DeliveryTrackingPage` in `AuthProvider`. Shows loading/error states.

10. **`/src/app/menu/page.tsx`** — Public menu page. Renders `PublicNavbar` + `MenuSection` + `PublicFooter` with `AuthProvider`.

11. **`/src/app/reservation/page.tsx`** — Public reservation page. Renders `PublicNavbar` + `ReservationSection` + `PublicFooter` with `AuthProvider`.

## Key Design Decisions

- **All redirects use `useEffect`**: `router.push()` is never called during render — only in `useEffect` — to avoid `ReferenceError: location is not defined` during SSR.
- **No changes to existing components**: All existing components (`AdminLogin`, `AdminDashboard`, `CustomerLogin`, `CustomerRegister`, `CustomerAccount`, `DriverLogin`, `DriverDashboard`, `DeliveryTrackingPage`, `PublicNavbar`, `MenuSection`, `ReservationSection`, etc.) work as-is.
- **PublicNavbar already accepted callback props**: `onAdminClick`, `onCustomerClick`, `onDriverClick` — no changes needed to the component. The callbacks now use `router.push()` instead of `setMode()`.
- **layout.tsx already has ThemeProvider**: No changes needed.
- **Each page wraps content in `AuthProvider`**: This ensures each route has its own auth context, which works correctly with Next.js App Router's independent route rendering.

## Verification

- All 11 routes return HTTP 200: `/`, `/admin/login`, `/admin`, `/client/login`, `/client/register`, `/client`, `/driver/login`, `/driver`, `/tracking`, `/menu`, `/reservation`
- No compilation errors in dev server log
- No SSR-related errors (location not defined)
