# Task 2.5: Image Upload Functionality for Menu Items

## Summary
Successfully implemented image upload functionality for menu items in the RestoProGN project.

## Changes Made

### 1. New File: `/home/z/my-project/src/app/api/upload/route.ts`
- Created a POST API endpoint for image uploads
- Authenticates admin via JWT (requires admin or manager role)
- Validates file type (JPG, PNG, WebP, GIF only)
- Validates file size (max 5MB)
- Generates unique filenames with timestamp + random suffix
- Saves files to `public/images/uploads/` directory (auto-creates directory)
- Returns the public URL path (`/images/uploads/<filename>`)

### 2. Modified: `/home/z/my-project/src/components/admin/MenuTab.tsx`
- Added `Upload` icon import from `lucide-react`
- Added `useState` import from `react`
- Added `apiFetch` prop to `MenuTabProps` interface
- Added `apiFetch` to destructured props in the component
- Added `uploadingImage` state for upload progress indication
- Added `handleImageUpload` function that:
  - Creates FormData with the selected file
  - Calls `/api/upload` via `apiFetch` (includes auth token)
  - Returns the uploaded image URL on success
- Replaced the simple "Image URL" input with an enhanced image upload section:
  - Text input for manual URL entry (existing behavior preserved)
  - "Télécharger" (Upload) button with file picker
  - Upload progress indicator while uploading
  - Image preview thumbnail (24x24 rounded) when an image URL is set

### 3. Modified: `/home/z/my-project/src/components/AdminDashboard.tsx`
- Added `apiFetch={apiFetch}` prop to the `<MenuTab>` component instance on line 347

## Technical Details
- The upload endpoint uses `fs/promises` for file system operations
- Auth is handled by the existing `authenticateAdmin` and `hasRole` utilities from `@/lib/auth`
- The `apiFetch` from auth context automatically includes the JWT Bearer token
- FormData is used for file upload (not JSON), which is the correct approach for multipart file uploads
- No new dependencies were added
