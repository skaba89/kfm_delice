# Task 1.1: Payment Webhook Bypass — HMAC Signature Verification

## Summary
Fixed a critical security vulnerability in the payment PATCH endpoint where any unauthenticated user could mark payments as paid by sending `{ webhook: true }` in the request body.

## Changes Made

### `src/app/api/payment/route.ts`
- Added `crypto` imports: `createHmac`, `timingSafeEqual`
- Added `WEBHOOK_SECRET` env var (graceful — empty string if missing → webhook auth fails)
- Added `generateWebhookSignature()`: HMAC-SHA256 of payment ID using WEBHOOK_SECRET
- Added `verifyWebhookSignature()`: timing-safe comparison of expected vs provided signature
- **PATCH handler**: When `webhook === true`, now requires valid `x-webhook-signature` header (HMAC-SHA256 of payment ID). Returns 401 if missing/invalid.
- **POST handler setTimeout**: Replaced direct DB updates with internal PATCH call that includes proper HMAC signature

### `src/lib/validations.ts`
- Added `webhookSignatureSchema`: validates 64-char hex SHA-256 format
- Added `webhookPaymentStatusSchema`: extends paymentStatusSchema with `webhook: z.literal(true)`

### `.env`
- Added `WEBHOOK_SECRET=WEBHOOK_SECRET_REDACTED`

## Security Properties
- **Fail-closed**: If WEBHOOK_SECRET is not configured, all webhook requests are rejected
- **Timing-safe**: Uses `timingSafeEqual` to prevent timing attacks on signature comparison
- **Format validation**: `webhookSignatureSchema` rejects malformed signatures before HMAC check
- **Admin path unchanged**: Non-webhook updates still require admin JWT authentication
